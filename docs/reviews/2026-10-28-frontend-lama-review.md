# InfiDao 前端独立评审：lama

评审日期：2026-10-28。入口为 `/InfiDao`，对应 `src/app/infidao`、`src/components/flow` 与 `src/lib/flow-browser`；工作区基准提交为 `4804938`。共享现网记录的发布为 `infidao-570e028e8b3ee676`，声明的源码提交为 `2152658`。两者并非同一提交；已核对相关前端差异集中在公开路径和元信息，本文主要涉及的 FlowStream、菜单、注脚和面板组件无版本差异，历史回退监听逻辑也相同。本评审未将旧首页搜索 MVP 当作当前阅读产品。

## 判断与方法

现有阅读场有明确的产品性格：经文沿同一条文字带进入焦点，短按转向，释义按需出现。需要优先改善的是读者离开文字流去操作之后，能否确认结果、找回位置，以及让自己的理解真正成为阅读的一部分。

本评审使用 `lama → appllama-app-design-skill`，只迁移其中的产品层级、导航语义、手势承诺、状态反馈和移动端可用性原则。现有 Next.js / WebGL 架构是本次评审的前提，没有据此要求 Expo、原生导航栈、系统配色或另一套字体。

证据分三类：

- **共享截图与交互观察**：主线程操作现网 `https://aitoshuu.me/InfiDao` 后提供的 2026-10-28 截图和[结构化记录](assets/2026-10-28/observations.json)；评审员本人没有操作浏览器。桌面为 1450×713；最终移动图为 390×844、DPR 2、触摸粗指针、无 hover。
- **源码确认**：能够从本地组件、状态和样式直接确定的行为。
- **待实际复验的推断**：代码支持风险判断，但尚无相应交互或实体设备证据；不记作实测通过或失败。

已先阅读知识图谱报告的 God Nodes 与 Community 3 / 7 / 10，再按当前入口追踪源码。设计依据主要是 optical-flow、connected / live-connected-reading、persistent-reading-graph、water-reading-interaction、inko-reading-keepsake 等计划，并核对后续排版决定。以下已确认规则仍有效：

- 保留黑底、康熙经文、水膜、钻石火彩、画质、连续滚动和显影。
- 64% 中央列与短句独立成行有明确确认；不把它们判作待恢复的普通文章宽度。
- 可见的“释义”“此刻回响”和出处小标题是有意删除的。出处和生成说明按需查阅，不要求恢复正文小标题。
- 释义已移到长按浮层；段落三个点已移除，由左滑及边缘把手进入统一抽屉。
- 经文字体保留，其余文字按 20 / 16 / 12、400 / 500 审阅；输入是附加交互，不新增强制开场问答、阅读回合或图谱画布。

对应依据：[正文简化](../plans/2026-10-21-008-feat-alternating-entry.md)、[64% 中央列](../plans/2026-10-21-013-fix-clause-lines-and-narrower-center.md)、[持续阅读图](../plans/2026-10-21-014-feat-persistent-reading-graph.md)、[默认水膜与长按释义](../plans/2026-10-23-flow-water-reading-interaction.md)、[纪念卡接入](../plans/2026-10-24-inko-reading-keepsake-integration.md)。较晚的明确决定优先于早期顶栏、段内操作和流内释义描述。

## 按严重度排列的发现

严重度定义：P1 会让读者的当前意图或位置发生实质偏离，应优先处理；P2 会增加犹豫、验证或寻找成本，影响持续阅读。没有提出 P0 问题。优先级用于后续设计排序，不构成本轮新增的实现授权或已通过验收的声明。

### L1 · P1 · 同页面板与浏览器返回没有形成一致的退回层级

- **用户情景**：读者已经沿词进入一条分支，在桌面或手机打开释义、温故、添一念或纪念卡，随后使用浏览器返回，想先收起眼前的临时任务。
- **实际行为**：主线程共享交互记录已复现：分支上的释义打开后，一次浏览器返回使阅读历史由两层变一层，释义同时关闭，焦点回到菜单把手。这证明一次返回同时离开了释义和分支。源码上，临时任务由组件状态控制；公共对话框逻辑处理 Esc、Tab 和焦点隔离，没有把浏览器返回纳入关闭语义；`popstate` 直接恢复上一条阅读路径。温故、添一念和纪念卡没有同样的统一收起逻辑，存在背景先换路径而面板仍在的风险；这三类风险尚未实测，不能与已复现的释义路径混称。
- **对概念与心流的影响**：读者为了暂时理解或保存一句话而离开流，却不能确信返回是在关闭任务还是退回自己的思考路线。连续阅读需要的位置安全感在这里失去一致性。
- **证据**：[共享记录](assets/2026-10-28/observations.json) 的 `branch.browserBackWithMeaning`、[返回后的画面](assets/2026-10-28/desktop-back-with-meaning.png)；[useFlowDialog.ts:25](../../src/components/flow/useFlowDialog.ts#L25) 只处理键盘关闭；[history.ts:21](../../src/lib/flow-browser/history.ts#L21) 处理路径回退；[controller-host.ts:50](../../src/lib/flow-browser/controller-host.ts#L50) 直接恢复阅读记录；[FlowStream.tsx:144](../../src/components/flow/FlowStream.tsx#L144) 在恢复时收起释义；[FlowExperience.tsx:518](../../src/components/flow/FlowExperience.tsx#L518) 独立挂载其他面板。
- **建议方向**：统一最上层临时任务的返回语义：第一次返回关闭该任务并保留本次读点，下一次才回到上次分支。关闭按钮、遮罩、Esc 和浏览器返回应到达同一个结果。返回只撤销导航，不撤销收藏或已保存注脚。
- **验收方式**：在 A→B 的已保存阅读中，分别打开四类面板；第一次返回仍为 B、位置不变且面板关闭，第二次返回才到 A；再检查前进、连续返回、刷新以及无前序分支的首次访问。使用已有记录即可，不必增加模型调用。

### L2 · P1 · 已保存注脚在手机被挤成单字竖列，桌面打开后可能落在屏外

- **用户情景**：读者在经句处产生自己的联想，从抽屉选择“注脚”；保存后再阅读或编辑自己的文字。
- **实际行为**：共享测量已确认两个问题。桌面 1450×713 中，点击注脚后输入区上沿为 y=719.1px，位于屏幕下方，焦点仍在菜单把手；在此次 390×844 样本中，输入区 y=371.3px 可见，因此不能笼统称为手机打开注脚必在屏外。保存后，注脚正文、“留成手写纪念卡”和“删除”放在同一个不换行的 flex 行里：约 249.6px 的列被 142px、62px 两个按钮及两处 18px 间隙占用，正文仅剩 **9.59px**，样例被挤成单字竖列，整行高达约 697.3px。这不是 64% 经文列本身的错误，是注脚操作布局没有适配这条列。
- **对概念与心流的影响**：“我”最直接的表达渠道反而需要寻找，保存之后的个人文字又可能让位给导出和删除操作。用户容易继续消费生成回响，而没有顺畅地留下自己的解释。
- **证据**：[共享记录](assets/2026-10-28/observations.json) 的 `notes.desktopOpening`、`notes.mobileOpening`、`notes.mobileSaved`；[保存样例被挤成竖列的移动截图](assets/2026-10-28/mobile-note-narrow-column.png)；[FlowStream.tsx:756](../../src/components/flow/FlowStream.tsx#L756) 的挂载位置；[FlowStream.tsx:781](../../src/components/flow/FlowStream.tsx#L781) 只切换展开状态；[NotesPanel.tsx:79](../../src/components/flow/NotesPanel.tsx#L79) 的输入和已保存行；[flow.module.css:539](../../src/components/flow/flow.module.css#L539) 的横向布局，以及 [flow.module.css:781](../../src/components/flow/flow.module.css#L781) 的正文收缩设置。共享样例为专门创建的非私人文字，已由主线程删除。
- **建议方向**：保留原有连续正文列。展开注脚时只进行一次明确的定位，让注脚标题或输入区进入视野；用户明确开始书写后再交付输入焦点，避免查看旧注脚就强制打开键盘。让已保存注脚正文独占一行，把编辑、纪念卡和删除放到下一行。不要通过缩小字号或加宽经文列解决操作挤压。
- **验收方式**：在 320px、390px 和横屏下，分别从短回响、长回响的经句打开注脚，用户应立即知道输入区已经出现；输入、保存、编辑、取消与删除撤销均保留所选经句。用短注脚和接近 1000 字的非私人样本核对正文宽度、键盘遮挡、按钮换行和保存后焦点。

### L3 · P2 · 收藏结果确认只写进了不可见状态区

- **用户情景**：读者想把一句经文留住，点击抽屉里的“收藏”，然后继续阅读。
- **实际行为**：菜单统一先关闭再执行操作。收藏状态更新后，结果文字写入 `srOnly` 的状态区；可见的“已收藏”按钮已经随着抽屉关闭。当前文字流也没有可见的保存标记。读者要重新打开抽屉，才能确认刚才是否保存成功。
- **对概念与心流的影响**：这个应当只用一次动作完成的收束动作变成“保存—再打开—确认”。不确定感会促使重复操作，并打断刚形成的阅读感受。
- **证据**：[FlowMenu.tsx:51](../../src/components/flow/FlowMenu.tsx#L51) 的先关闭动作；[FlowMenu.tsx:37](../../src/components/flow/FlowMenu.tsx#L37) 的状态更新；[FlowMenu.tsx:91](../../src/components/flow/FlowMenu.tsx#L91) 的仅辅助技术可见状态；[FlowExperience.tsx:433](../../src/components/flow/FlowExperience.tsx#L433) 的保存逻辑。该项由源码确认，未把未知的保存服务结果当成成功。
- **建议方向**：在现有阅读场内给予短暂、安静且可见的“已收藏 / 已取消收藏”确认，同时保留读屏状态。确认不要求关闭按钮、不移动正文、不触发庆祝动画，也不需要再开启一个任务。
- **验收方式**：收藏及取消收藏各一次即可明确识别结果；快速连点不产生相反的误读，存储失败显示相应提示。确认消失后，阅读位置和流动状态仍与操作约定一致。

### L4 · P2 · 首次提示解释了五个手势，却没有先把读者的第一步说准确

- **用户情景**：第一次看到黑底经文的访客，想先停下来看清，再判断是否继续探索。
- **实际行为**：首屏唯一说明是“点一下停驻，点词接续；上下滑动继续，长按释义，左滑菜单”。“点一下”没有指明空白区域，而经文字词本身就是接续按钮；首次点击一个词可能触发转向，而非访客理解的单纯停驻。提示同时承载五项动作，没说明“添一念”和“自己的注脚”如何体现“我”。右侧入口可点击区域充足，但可见部分是一条低对比细线，需要提示才能理解其用途。
- **对概念与心流的影响**：进入沉浸场之前，访客先面对操作解码；一次误转向又缺少页面内明显的退回线索。产品容易先被理解为自动播放经典和建议，而不是读者通过词与自己的念头塑造阅读。
- **证据**：[桌面初始阅读截图](assets/2026-10-28/desktop-reader.png)、[桌面抽屉截图](assets/2026-10-28/desktop-menu.png)、[390px 阅读截图](assets/2026-10-28/mobile-reader.png)、[390px 抽屉截图](assets/2026-10-28/mobile-menu.png)；[FlowExperience.tsx:512](../../src/components/flow/FlowExperience.tsx#L512) 的提示；[LinkedText.tsx:89](../../src/components/flow/LinkedText.tsx#L89) 的直接转向；[flow.module.css:213](../../src/components/flow/flow.module.css#L213) 的边缘把手。共享测量确认手机菜单触区为 44×96px，不把可见细线误当成实际触区过小。
- **建议方向**：先把现有提示改成明确的“点空白停驻，点词接续”，按读者当下状态逐步提示后续操作。在现有抽屉中分清“当前经句”与“自己的阅读”：释义、原文、收藏、注脚属于前者，添一念、温故属于后者；纪念卡保持低频收束动作。首次说明可用一句话交代“可以沿词阅读，也能添入此刻一念”，不增加强制输入页或正文小标题。
- **验收方式**：让不了解产品的新访客仅凭页面先完成停驻，再主动沿词转向，并找到添一念与自己的注脚；观察其是否把“点一下”理解成任意点击。手机首屏提示可完整读完，且不与底部续读操作相互遮挡。

### L5 · P2 · “同一句经文”与“这一次阅读”在回找时不够容易区分

- **用户情景**：读者从不同词或不同一念多次经过同一句经文，想回到上一次有用的理解，而不只是找到这句经典。
- **实际行为**：规范节点和访问路径在数据层分开保存，这是正确的；当前流只呈现经句与回响，没有渲染本次选择词或一念来路。抽屉显示出处及动作，没有使用已有的 `returnToParent`。温故“最近阅读”以经句、出处和日期标识路径；同日多次经过同句时，列表不能直接说明是哪一次。原一念与关联仍可在“关联”页查找，因此这里是回找成本，不是数据已丢失。
- **对概念与心流的影响**：读者的思考路径被弱化成一串经句。循环重访在数据上成立，用户却需要额外浏览才能重新辨认自己为什么走到这里。
- **证据**：[移动温故图](assets/2026-10-28/mobile-library.png)、[共享记录](assets/2026-10-28/observations.json) 的 `mobile.library`；[continuity.ts:29](../../src/lib/flow-browser/continuity.ts#L29) 保留访问路径；[FlowStream.tsx:737](../../src/components/flow/FlowStream.tsx#L737) 的流内显示；[FlowMenu.tsx:95](../../src/components/flow/FlowMenu.tsx#L95) 的抽屉内容；[controller-host.ts:94](../../src/lib/flow-browser/controller-host.ts#L94) 的现成返回能力；[LibrarySheet.tsx:61](../../src/components/flow/LibrarySheet.tsx#L61) 的最近阅读行；[KnowledgeLibrary.tsx:70](../../src/components/flow/KnowledgeLibrary.tsx#L70) 可查看直接关联。
- **建议方向**：在现有抽屉和温故列表内提供简短的“沿某词 / 这一念”来路，必要时提供返回上次读点的动作。阅读主体仍是一条文字流；不增加常驻面包屑、回合边框或图谱画布。经文节点与一次访问应继续区分，避免用新标题覆盖原经句身份。
- **验收方式**：以 A→B→C→A 以及两条不同一念到达 A 的已有路径检查；读者能在抽屉辨认本次来路，并在温故中选回正确的一次阅读。旧路径缺少一念信息时使用可理解的降级文案，不伪造来路。

## 需要用户决定的产品取舍

1. **“我”的提示放到哪里。** 已确认的极简正文和附加输入继续成立。若要增强概念可理解性，建议只调整首次提示、现有抽屉和温故来路；是否增加更明确的“这一念”提示属于产品取舍，不能把它当作已批准的新入口。
2. **生成回响的身份如何按需说明。** 当前把出处和 AI 生成说明放进完整原文，是已确认的简化。可以在首次说明及既有释义浮层中补充“生成解释供参照”，让读者知道这是一种参考理解；这不意味着恢复每段的可见小标题。未经用户决定，不把已确认的无标签正文记为必须撤销的缺陷。
3. **轻收束还是定制导出。** 现有纪念卡是一项完整的内容选择、字迹、纸面、准确文字确认和异步制作任务；三张预制卡在独立 `/InfiDao/keepsake` 页。若希望“读到这里，留一句”成为轻收束，需要决定主阅读是否接入现有预制卡，以及与当前经句定制制作的关系。不是强制结束阅读，也不把独立预览页的存在等同于主流已经接入。

纪念卡当前用编号筛选与字迹名称选择，制作前没有笔迹预览（[ReadingKeepsakeSheet.tsx:208](../../src/components/flow/ReadingKeepsakeSheet.tsx#L208)；[移动纪念卡图](assets/2026-10-28/mobile-keepsake.png)）。这会增加第一次选字迹的不确定性；可考虑保留默认值，将更多选择收进可选设置，再展示少量静态字迹样本。该方向需与零生成费用及现有素材能力一起确认，不能通过自动生成试写增加费用或发送。
