# 阅读器可读性与召回复验

以 `e3e0b28` 为对照。Astra 制定验收口径并独立复核，Sol 执行。可读性和召回复验各自验证并推送到现有分支。使用封存计划和合成阅读路径，本轮无需调用模型。

## 第一项　可读性与到达交互

- 手机端将回响和释义正文左齐、放宽并自然换行。保持经句居中、原列宽和字形，兼顾 320 和 390 像素宽度及桌面。覆盖流中的回响和长按或键盘打开的释义。
- 停驻和等待时减弱字形折射与色散。滚动含手动与自动两种，沿用原有滚动效果。正向渲染与反向命中共用同一帧光学参数，静止完成后保持既有按需绘制。系统减弱动效、原生文字回退和开场顺序都纳入校验。
- 经句在主要阅读区外时，「去读」留在独立于文字的区域。读者主动按下才滚动并聚焦到新句。保留触摸目标、遮层避让、已读位置、键盘焦点、历史、取消和重试。
- 等待只显示点中的词和接续状态。首次接续由现有关联核验放行，已核验锚点和同上下文复用可走现有首句路径。公开主入口为 `aitoshuu.me/InfiDao`，`tongye.me/InfiDao` 为同步入口。
- 用同一定格的经句、回响和释义对比停驻、等待、到达与跳转。截图和浏览器交互验收同时检查无横向溢出、无字形遮挡、触点命中正确词位及历史恢复。用户已确认本轮使用 WebKit 验证并推送分支，iPhone Safari 真机单列待验。

## 第二项　冻结证据复算

- 使用 `docs/qa/flow-blind/2026-11-25-plan-stability-{contexts,plans}.json`。两个诊断读点各三轮用于分析，四个既有留出读点各三轮用于核对。基准在每轮调用现有 `candidatesFor` 和 `compactCandidates`，与既有有序候选范围对账。
- 对照保留指定原句与核心池前六个候选。其余核心候选按不同规划词原序轮流取各自排序的下一有效来源，每个来源只占一位。缺席位置沿用基准顺序，核心与诗词仍按原规则交替。比较两侧前 40 和实际送模前 12，记录证据组新增或丢失、逐字与规范化后的词语覆盖。诗词索引限额之外的逐字覆盖记作未知。
- 比较同时按轮次和不同读点给分母。盲评以去重的实际原文窗口为单位，评估是否能直接接续，区分已经具备的证据与方案新增证据。实验须在诊断集增加至少一组直接送模原文，在留出集至少有一个读点增加可用证据，并保留各组原有的强证据。复跑材料随结果交付。生产排序须有单独确认的发布条件。
