# 阅读动效与分支接续

以 `8f959d1` 为本轮对照。Astra 复查和验收，Sol 实现。在现有分支分批推送。

## 第一批 · 原生文字与水面调度

WebGL 不可用或上下文丢失时，原生文字已经接管。停驻时水面采样仍会让阅读器周期性绘制。当 `StreamGlass` 报告 `unavailable` 或 `lost`，`FlowStream` 在现有水面采样入口停止微波。滚动、布局和焦点继续触发原生绘制。上下文恢复沿用现有失效通知，接回动态水面。

满画质轻点停驻会冻结仍在入场的段落。现有调度把已冻结段落计为活跃，即便位置和光能已稳定，停驻微波仍占满帧。保留冻结段落的恢复能力，用渐入和墨迹采样的实际推进状态驱动原有帧间隔策略。停驻采用已有 50 ms 采样间隔，重新滚动、字形继续显现和透镜变化时回到逐帧。画质档、出水时序和字形材质沿用既有约定。

验证停驻取样、滚动唤醒、上下文丢失和恢复，以及冻住的笔画与恢复推进。满画质停驻应保留微波，空闲后自主回调预计不超过 32 次 / 1.5 秒。原生回退的停驻自主回调预期为 0 次。满画质对照验证动态水面和约 1.1 秒的开篇出水。停驻样本衡量调度次数。

390 × 844、DPR 3 的 Chromium 以同样经文停驻，满画质的 1.5 秒回调数从 90 降为 28–29。关闭 WebGL 与主动丢失上下文两种场景都从 90 降为 0，原生滚动 85px 后重绘并再次停稳，恢复上下文后采样到 29 次。满画质 2 秒定速滚动的帧间隔 P95 为 17.5 → 17.4 ms，出水约 1.1 秒。样本不足以判断真机帧率或耗电。Astra 独立核验了 136 项测试和 5 个冻结材质快照。

## 第二批 · 分支抵达与阅读中断

分支抵达时，保留原来的读点。阅读选项、释义或工具面板盖住正文期间，阅读器暂缓「去读」提醒，也暂缓判定目标已经读到。遮挡解除后，用当前标题位置决定提醒是否需要出现。提示与当前抵达事件绑定。读者按「去读」时才定位和聚焦标题。

`FlowExperience` 将添一念、温故、纪念卡及开场遮罩的可见状态作为 `arrivalObscured` 传入 `FlowStream`。`FlowStream` 合并菜单实际可见期与释义状态。布局测量同时按 `entryKey` 建立经句标题索引，滚动检查和「去读」共用它，复用既有 18% 至 68% 阅读区与定位逻辑。

验收覆盖遮挡期间目标短暂进入阅读区、关闭时目标在区内或区外、新抵达替换旧结果、标题更新与重测。以固定分支数据检查滚动全树查询数、关闭后的提醒、主动定位和键盘焦点。
