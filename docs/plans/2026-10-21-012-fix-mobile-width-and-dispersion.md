# 修正中央行宽与原玻璃色散

> 后续反馈（2026-10-21）：用户认为本版色散过于纯色，偏离原版钻石火光。色散增强部分由计划 015 修正；正文列宽后由计划 013 收窄至 64%。本页保留当时实现与检查记录，不代表当前视觉方案。

用户指出上一轮光栅观感不足，要求回到原有色散；手机中央仍太宽，缺少上下宽度对比。本轮按已确认的“中央较远且清晰、上下靠近并模糊”修正，保留字体、逐字浸染、同一原生阅读流及导航。

## 原因

- 手机正文只有左右 24px 内边距：390px 屏幕实际文字区为 342px，约 88vw，没有落实中央收窄。
- 手机焦距 1400px 修复了纵向拉高，但同时减弱了横向近大远小；不能仅靠该相机距离产生足够的宽度对比。
- 上一轮增加了独立的屏幕空间光谱贡献，对原玻璃透射本身的色散分离帮助有限。

## 修正范围和接口

- `flow.module.css`：连续正文列宽为 72%，最大文字宽度 692px，取消重复的水平 padding；桌面原 760px 容器扣除两侧 34px 后本来就是 692px，因此桌面正文行宽保持。手机保留当前 30px 经文字号。
- `stream-bend.js` / `bend.ts`：保留纵向连续圆弧与当前焦距，在共享 Bend 参数增加移动端 `flare`。横向展开随现有曲面深度平滑增加，600–900px 屏宽间回落至桌面原投影。正向投影、逆向命中与最终着色器使用同一公式，中央不缩放字形。
- `renderer.js` / `stream-glass.ts`：撤下上一轮独立光栅贡献，恢复只通过原两次玻璃透射产生色散。最终外围加强波长折射率差异，收拢过散的粗糙采样，提高原折射中彩色分量的清晰度；中央保持原材质强度。继续读取已浸染的文字缓冲，沿用一次 Bend，无新增绘制通道。
- 原生按钮、字体、逐字显影、减少动画与图形故障降级保持现有接口；只在共享 Bend 参数里扩展横向展开系数。

## 验收

1. 手机实际正文列宽为 72vw；390px 下约 281px，320px 下约 230px，不以缩小字号代替收窄。
2. 以同一列边界测量：手机上下 20% 高度处的投影宽度至少是中央的 1.23 倍，上下 10% 处至少是 1.45 倍；纵向仍缩短，不恢复之前的拉高。
3. 原色散形成可见、柔和而有分离的彩色折射，中央可读；桌面、手机、窄屏、横屏无布局溢出或图形错误。
4. 正逆投影、连续曲率、原生点击、触摸、焦点、浸染同步、减少动画、图形恢复回归；实际页面用保存内容验证，新增模型调用为零。

本轮不提交、推送或发布，不创建 agent、分支或 worktree。

## 实现与检查结果

- 已按上述范围完成：手机列宽实测 280.80px / 230.40px，字号仍为 30px；1440px 桌面正文宽度仍为 692px。
- 390px 手机同一列在源坐标 20% / 10% 高度的投影宽度分别为中央的 1.264 / 1.505 倍，下半部分对称。实际 GPU 横向展开参数与点词投影参数一致。
- 已撤下独立光栅采样，改为增强原玻璃透射的色散分离与彩色分量。
- 8 组、85 项测试及类型、ESLint、JavaScript 语法检查通过。桌面、手机、窄屏 18 处投影点击全部正确；暂停、显影中触摸点词、键盘、减少动画与图形恢复通过。
- 视觉预览、四种视口及验证边界见 `docs/qa/web-flow-migration/2026-10-21-mobile-width-and-dispersion.md`。技术检查不等同于用户确认视觉效果。
