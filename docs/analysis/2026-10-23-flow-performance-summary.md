## 本轮进展

已去除新行的两次整块像素读回，接触梯度按变化行上传；增加阶段诊断、合并布局通知，并按有效宽度及折叠带限制绘制。本轮 422 项 Flow + 124 项共享逻辑测试通过，52 组画面对照逐像素一致。冻结基线、U2 中间版、最终版的桌面首次快滚 CPU P95 分别为 13.3、4.3、5.0ms，但电源状态前后不同且切换时刻未知，不能将全部差值归于代码。最终结果见[执行记录](../qa/2026-10-23-flow-60fps-execution.md)。

普通模式直接启用 GPU 缓存未通过画质对照，未启用；最终普通桌面快滚约 3.1 FPS，仍有明显停顿。长历史候选新旧同轮均未复现旧秒级停顿，原因仍未确定。结束控制页约 29.20 FPS；用户要求保持设置，本轮没有修改系统电源设置，最终观察到的接电低电量模式已关闭，因此不能将约 30Hz 节奏归因于该开关。

## 还要验证什么

1. 控制页约 30Hz 的具体原因；历史控制场景也出现过约 60Hz，不是恒定上限证据。
2. 新字形优化后在更长轨迹、不同设备上的峰值；现已去除整块像素读回并加入阶段计时。
3. 长历史布局重测、离屏绘制、合成/GPU 调度与秒级间隔的关系。
4. 当前构建主要 GPU 通道成本，以及可证明安全的绘制范围。
5. 普通 current 模式的独立性能与 GPU 字形等价适配，尤其手机原有 9px 模糊。
6. 同条件 30 秒 × 5 轮的实际呈现验收，及真机手机。

## 接下来先做什么

按统一方案的 U0–U6 执行：
- 已完成文档校正、冻结基线、模式诊断和去除整块读回。
- 先定位普通模式的停顿及未通过画质的缓存差异，继续核对历史长间隔原因。
- 校准当前 GPU 通道成本，再扩大可证明安全的范围优化。
- 获得可验收的绘制节奏后，执行正式呈现验收；不把约 30 FPS 的环境诊断当成通过。

## 不再使用的结论

删除“每帧仍遍历全历史”“悬停仍清空整个缓存”“有效源范围不能收缩”“缓存满必须全清”等过时现状描述。

CPU 15–20ms、GPU 3–5ms、总收益 10–16ms 和 4–6 周工期均不足以作为当前版本事实或承诺。CPU、GPU、合成存在流水关系，不能简单相加后取倒数推 FPS。

水膜降频、模糊量化和新增逐行入水行为没有纳入本轮无损性能修复。默认模式和候选开关保持既有行为。
