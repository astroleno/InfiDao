## 扩容前冻结的预算

按已批准的有界本地索引架构，固定以下实施准入门槛；测量失败先优化或修复，不在看到结果后放宽。

| 项目 | 门槛 | 测量方式 |
| --- | --- | --- |
| 核心内容身份与排序 | 上述固定查询结果及既有回归不变 | 完全关闭诗词，在同一环境比较 ID 与顺序 |
| 诗词独立索引 | 最多 16 个只读分片，单文件小于 50 MiB，总量小于 2 GiB | 全部产物统计与 SHA-256 |
| 首次校验与启用 | 本地索引完整校验不超过 8 秒 | 新进程、冷应用缓存；注明操作系统页缓存状态 |
| 暖诗词召回 | p95 不超过 500 ms | 固定不少于 20 条主题、篇名、作者、原句及单字查询，各 3 次 |
| 暖作品读取 | p95 不超过 100 ms | 固定修订与短篇/长篇样本，排除网络与模型 |
| 进程内存 | 完成核心加全量诗词检索后 RSS 峰值不超过 512 MiB | 隔离测量进程；不能读取整个语料作为运行时索引 |
| 浏览器正文 | 首屏不下载诗词库；全文按需读取、缓存上限 32 首 | 浏览器网络及存储记录 |

首句与续读额外记录检索、生成、核验的阶段时间；在同样的模型回放下验证本地部分满足以上预算。真实模型、腾讯生产机器和物理手机结论单列，不用本机数据代替。

## 数据与索引选择

上游固定为 `palemoky/chinese-poetry@041b8ab50bdf07bf498bba2d1666b1d1fd707f4e`。365 个来源文件以 Git blob SHA-1 逐个核对，仅处理正文与作品基本信息，现代注释、译文、作者传记和上游程序不纳入发布。

本地索引使用 Node 内置 SQLite 读取不可变文件，包含作品正文、片段、来源映射、FTS5 字词/意象索引和 64 维本地派生向量。它是计划中预构建分片索引的具体实现，不新增运行服务、网络数据库或安装全局依赖。核心路径不初始化 SQLite；生产已有 Node 24.22.1 支持该能力。生成环境与 SQLite 版本记录于质量报告，已发布产物按字节校验，腾讯不重新生成数据。

简繁检索归一化只使用 OpenCC 1.1.9 的字典派生映射，保留其许可证，不改规范原文。参见 [Node SQLite 文档](https://nodejs.org/docs/latest-v24.x/api/sqlite.html) 与 [OpenCC 数据来源](https://github.com/BYVoid/OpenCC/tree/ver.1.1.9/data/dictionary)。
