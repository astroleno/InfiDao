# 2026-10-01 经轮渲染与阅读连续性迭代

## 范围

针对桌面经轮卡顿、静读点词后重新滚动、生成等待提示离操作位置较远，以及输入面板提交后失焦的问题，沿用现有共享渲染器、阅读记录与内容协议完成本轮修改。未修改生成额度、模型、内容核验规则或个人注脚上传边界。

## 实现

- 网页经轮每次浏览器动画回调绘制，移除原来至少间隔 32ms 的限制；小程序默认仍为 32ms。
- 网页两张折射缓冲图的宽高各为可见画布的 50%，单张像素数为 25%。最终文字、背景与前玻璃仍在完整画布上绘制。三次绘制目标的总像素面积由约 3 倍画布降为 1.5 倍；这不是 GPU 耗时或整体帧率提升 50% 的测量结论。
- 行窗口更新只提交一次场景；字形上传、主文字分辨率、八次折射采样与玻璃造型保留。停止阅读、切后台、上下文丢失仍停止动画。
- 共享控制器为新分支提供父级快照上下文，网页只继承最新的停驻状态。新分支使用新的经轮位置、原文折叠状态和阅读滚动位置；返回已有分支恢复其自身快照。小程序宿主忽略新增上下文，保持既有过场。
- 静读等待提示位于阅读头部，展示点选词与停止入口；输入生成提示位于输入面板内部。12 秒未收到首句后说明等待较久，不冒充实际服务端阶段；收到首句后才显示补全联系。
- 提交输入后焦点转到停止按钮，停止或失败后回到可编辑输入框；保留草稿与原有弹窗隔离、Esc 返回行为。移除覆盖整个主区域的 `aria-busy`，避免其中的等待播报被延迟到请求结束。
- 单次模型调用超时返回 `MODEL_TIMEOUT`；有候选但生成内容未通过核验返回 `RELATION_UNVERIFIED`，与没有检索候选的 `NO_BRANCH` 区分。错误事件结构不变，也不自动追加模型调用。

## 验证

- 25 个相关 Jest 文件、119 项测试通过；小程序 124 项回归通过。应用与脚本类型检查、ESLint 通过。
- 浏览器实际观察两张离屏目标为 1127×554，最终画布为 2254×1108；渲染单测验证三次 viewport 与网页/小程序各自的帧间隔。
- 本地浏览器通过模拟内容响应验证：静读点词后新分支保持静读，返回父分支也保持静读；等待提示展示所选词且位于阅读区域。
- 320×740 输入面板没有横向溢出，停止与返回按钮位于可见视口；提交后焦点在停止按钮。取消后实际焦点为 `flow-seed-input`，草稿“慢慢做好”保留；Esc 关闭后焦点回到“一念”入口。
- 模拟请求用于验证界面与取消，不作为真实模型速度或生成质量的证据。真实设备持续帧率、iPhone Safari、微信内置浏览器与 VoiceOver 仍待验收。
