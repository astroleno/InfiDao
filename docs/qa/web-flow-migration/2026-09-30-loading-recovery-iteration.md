# 字体加载与失败恢复迭代

## 范围

按已批准网页迁移方案继续验证和优化，不改变经轮设计、内容协议、语料、模型或调用额度。当前 UTC 日的上一轮内容测试会话已达到 5 次调用，本轮没有换身份或绕过预算继续调用 DeepSeek。

## 修改

- 服务端 HTML 预加载当前发布的字体清单，客户端复用同一个 URL。
- 所需字体分片最多 3 个同时下载，限制跨并发调用共享；同一分片和 FontFace 仍去重。完成顺序不改变字体优先级，保留大小/SHA-256 校验、CDN 失败后的同源回退以及失败重试。
- 已注册的基础字体不再重复解码 base64。
- 输入弹层内部显示失败原因并滚动到提示；断网和格式错误使用可读提示。
- 请求期间可停止展开，保留已输入内容；关闭弹层会取消未完成请求，防止迟到结果改变下一次弹层状态。

## 验证

- 20 个相关测试文件、103 项测试通过，类型检查和 lint 通过。
- 第一轮完整回归发现字体未覆盖的拒绝顺序发生变化：原本应报告 `FONT_UNCOVERED` 的输入提前进入 FontFace 注册。已恢复先检查字形覆盖，再并行准备资源，重新运行全部 103 项通过。
- 浏览器在 844 × 240 下模拟预算拒绝、断网、等待中取消，以及重放上一轮已验证的“想睡觉”响应。提示位于弹层内且可见；取消发出 abort、输入保留、弹层保持打开；重试成功后弹层关闭。模拟响应不是新的 DS 内容质量样本。
- 浏览器探针拦截所有 `/api/flow` 请求，性能采样只恢复已有阅读，不消耗模型调用。未清空浏览器阅读、注脚或 Redis。

## 性能方法与基线

同一 Chromium、390 × 844、DPR 3、不限制网络/CPU，记录经轮画布第一次向默认 framebuffer 绘制的时间。已有阅读恢复场景，不是新访客从输入到生成的端到端耗时，也不代表 iPhone 性能。

优化前版本 `infidao-c3f5393613ce1a8f` 的 3 次禁用缓存样本：6443、9147、3956ms，中位数 6443ms。第一个样本字体清单在 3227ms 才开始，两个分片依次在 4604ms、5598ms 开始。允许缓存后先访问一次，再次访问经轮首绘为 1370ms。

基线记录：`output/qa-2026-09-30/iteration-baseline-samples.json`、`iteration-baseline-warm.json`。测试注入脚本只在 `output/` 下，没有进入应用发布包。
