# 点词冷点击分阶段实测

2026-11-26 晚间（台北时间），在同一隔离生产构建上对《大学》开场的首个「静」`[11,12)` 连续测了 5 次。记录了同一词位从点词到首句可读的原始耗时，P50 为 **3,928.2 ms**，最大 **4,216.1 ms**。5 次都通过服务端最终关联核验，首条引文与最终引文一致。

## 测量环境与口径

- 以 `159d0b88c8448daa7cc3f22a76b336ac155b4bf7` 的干净快照加本批两个计时源文件执行 `npm run build`。构建 ID `HZVvS92oKOKZk13SgK4CC`，发布标识 `infidao-35146ca74ffe7ef7`，源码 SHA-256 `62484bac6e34144235e1262303d0222c159cf1e618b5ea2a81110ce7c328b7fc`，页面入口 SHA-256 `913630add071782a0d39f0415bd850b219c20f4820e027a9eedbcbfe119838dc`。逐次核对页面引用，首末核对构建资源，使用相同的已核对语料。
- 回环 HTTPS，Redis 7.4.11，Node 26.7.0，已配置的 `deepseek-flash` 服务。使用桌面 Chromium 151，视口 390 × 844，DPR 3。此组使用一个常驻服务进程，公网版本和 iPhone Safari 单独验收。
- 每次使用全新浏览器上下文、会话和开场链。沿用 `scripts/probe-flow-public.mjs` 的开场、停驻、可信坐标点词和引文对照步骤。先点空白让流停驻，再按实测坐标点击「静」，验证 `text:11:12` 和语料哈希。每次只放行一个 `open` 和一个 `branch`，拦截了 4 次预取。通过首条引文和最终帧的原文、来源、哈希与范围确认交付一致。各分支有 3 次模型调用，合计 5 个开场与 5 个分支使用了 25 次调用。
- `FLOW_TIMINGS=1` 记录每次请求的规划、检索、生成和复核时间。`firstQuoteMs` 从服务流程开始计到第一个含引文的 NDJSON 事件成功入队。`reviewToFirstQuoteMs` 从进入复核计到同一时刻。复核前已交付引文时，该字段为空。缓冲的 JSON 响应没有流式入队时间。模型时间已经包含在各阶段中。
- 浏览器读到该引文的 NDJSON 行后，用连续两帧核对整句在视口内、无折光和遮挡、位置稳定，记录首个合格帧。5 次均从 `head` 收到引文。第 2、5 次需要点击「去读」，原始耗时各保留了 96.0 ms 和 116.9 ms 的等待。
