# 逐段返回验证与接入

用户要求先测试效果，特别验证原生小程序可用，再接入阅读链路。本轮不修改全屏经轮、停驻阅读入口或字体视觉，也不部署外部服务。

## 已确认目标与接口

- 沿用 `open / branch / next`，服务端只返回真实语料中核验过的引文。
- 先返回已准备的原文，再补当前节点的完整解释与词入口，随后补后续节点。
- 模型输出经过完整句与关系校验才变成可读解释；入口发布后身份及文字范围稳定。
- 前端按节点准备字形。旧内容、父链快照和经轮位置在等待或失败时保留。
- 返回祖先与重访已读子链使用本地快照，不重新生成已读内容。

## 验证顺序

1. 独立本机探针：原生 `wx.request` 接收分块；中文跨字节边界、取消与完整响应兼容；真实 DS 非思考文本能在完成前到达。
2. 比较当前整批生成与优先单节点生成：记录首个核验节点及全部内容耗时，审读实际文本，不用首个网络包代替可读时间。
3. 前两项证明可行后接入原页面，验证流动、停驻阅读、点词、后续补入与历史恢复；回归取消、失败和后台中断。
4. 记录模拟器与真机的区别。没有手机实际结果或 HTTPS 部署证据时，不宣称手机上线或真机验收通过。

## 验收

- 小程序接收到至少两个完成前的内容分块；中文、标点、扩展汉字无损。
- 首个核验节点可单独展示，后续准备不锁住已完成节点的点击。
- 可见经句和已有入口不被迟到结果替换，取消后的旧请求不污染新链。
- 同一链的连续追加、分叉与返回均保留经句身份与阅读位置。
- 将时间、样本量、语义问题及环境限制写入本文件。

## 第一阶段结果

原生开发者工具 2.02.2608060、基础库 3.17.3、iPhone 模拟器。连接本机代理，代理调用真实 `deepseek-flash` 非思考模式。没有向小程序传递 API 密钥。

- 人为拆开汉字字节的三段内容完整恢复，包括 `𠮷`；原生收到 6 个网络分块。
- 真实 DS 短文收到 24 个网络分块，首个文本片段 514 ms，完整文本 1055 ms。仅一次短文探针，不是原义复核完成时间，也不是手机网络 P95。
- 200 ms 发起中途取消，203 ms 收到 `request:fail abort`，没有完成事件。
- 使用既有 `createEventDecoder` 解析，没有使用模拟的 `wx.request`。
- 初次请求被域名校验拒绝，探针在本机 private 设置临时允许 localhost 后成功；正式配置仍需要合法 HTTPS 地址。

## 单节点与整批对照

三个固定公开测试输入；每个输入共用同一次检索准备，交替执行顺序，均保留原文核验和模型关系复核。表中时长从节点生成开始至复核完成，不包含检索准备与字体、画面承接。

| 输入 | 原整批首段可用 | 单节点首段可用 | 共用检索准备 |
| --- | ---: | ---: | ---: |
| 不知道先做哪件事 | 8942 ms | 3938 ms | 1256 ms |
| 一直准备未开始 | 8188 ms | 3744 ms | 1426 ms |
| 倾听时忍不住插话 | 7979 ms | 4500 ms | 1237 ms |

小样本中位数从 8188 ms 降至 3938 ms，约减少 52%；不能据三个样本报告生产 P95。这里只比较首个可用节点，后续阅读仍会产生生成与复核调用，不代表整条链总成本减少 52%。

单节点仍能提供真实引文、完整短解和 2–3 个经过复核的入口。整批倾听样本中仍出现将「听其言而观其行」解释为观察说话状态的问题；性能验证没有解决全部经学释义与关联质量问题，仍需要独立审读。

## 接入选择

依据上述结果，每个 `open / branch / next` 优先交付一个完整核验节点。既有 `head` 事件继续先送可信原文；完成节点附带后续游标，后续准备交给现有后台预取。模型的结构化 JSON 仍按完整节点解析，未把未经复核的逐字输出直接放进阅读页。

同时补齐已读子链重访：按父链、原节点与入口 ID 找到本地快照，恢复停驻、旋转、经句窗口与阅读滚动；已走过入口不再发起后台分叉预取。既有全文经轮、字体和色散保持。

## 原生页面接入结果

实际 `/api/flow` 服务、真实模型、原生 `wx.request`、真实字体与 WebGL 页面；没有用浏览器页面代替小程序。

| 检查 | 结果 |
| --- | --- |
| 默认开场 | 原文事件 301 ms；完整节点事件 4330 ms，页面获得完整节点 4353 ms |
| 后续补入 | 3903 ms；原有首句 ID、引文不变，仍然无限环流 |
| 点词分叉 | 原文事件 319 ms，完整节点 4027 ms；目标与原入口核验的出处一致 |
| 返回与重访 | 父链及子链 ID、位置、行相位、停驻状态、原文开关、阅读滚动和经句窗口均一致；重访该入口没有新增该入口的模型请求 |
| 原生画面 | 阅读与原文实际按钮可用；全屏经轮、字体与色散保持，WebGL 错误为 0 |

网络事件计时不等于首帧显示；本轮没有新的手机首帧 P95 测量。重访时允许预取子链的其他入口，不能把这些后台请求误算成对已读入口的重新生成。

接入中发现并修复两处真实问题：

1. 原文 head 提前出现后，自动后续请求可能取消尚未完成的开场解释。小程序现在等待当前节点完整后再取后续，服务端也拒绝未完成首节点的游标请求。
2. 切链时原生滚动区会发出布局归零事件，覆盖保存的阅读位置。恢复使用独立保存的目的位置，并在阅读层提交后应用，已在原生页面复测。

相关回归：小程序 80 项测试、服务端节点与关系 12 项测试、小程序静态检查、应用及脚本 TypeScript 检查、变更服务端与探针脚本 ESLint 通过。历史查找也覆盖了同一入口遗留失败记录、随后重试成功的情况。

另测两个固定公开输入的完整 HTTP 打开及分叉：

| 输入 | 打开完整节点 | 分叉原文事件 | 分叉完整节点 |

| 同时接了太多项目 | 5563 ms | 300 ms | 3775 ms |

非空一念需要先检索和准备，因此本轮仍没有默认开场那样的即时原文。以上四次请求均通过结构与真实引文检查，但不能据此认定释义合格：后一个样本将「藏器于身」的「器」直译为器具，并以继续等待来联系迟迟不敢开始；分叉后的「凡事豫则立」联系较清楚。前一阶段倾听语境的问题也仍须审读。当前二次复核并非可靠的古义真值来源，生成质量尚未通过独立标注验收。

本轮代码接入只证明逐节点流程可运行；默认仍为精选模式。没有部署外部服务，也没有 iPhone / Android 真机、手机弱网或长期内存结果。

## DS Platform 与手机接入

本节记录的是本轮最初验证的 HTTP 路径，不是小程序唯一可用的架构。DS Platform 提供模型 API；项目当时的 `/api/flow` 内容服务负责取真实语料、核验引用、保存在线链路及调用 DS，密钥只在服务端。

只有继续采用这条 HTTP 路径时，才需要部署该服务并配置微信合法域名。其会话存于进程内，重启会使新的在线请求失效，多实例或持久化要求还需补共享会话存储。

用户随后明确要求把业务逻辑放回小程序，并保留当前测试 AppID。`ref/infinite-wiki` 本身也是客户端直连模型；它没有证明独立内容服务的必要性。检索、核验、链路和历史可以在端上执行，模型调用及凭证处理应单独解决。后续验证与当前架构方向以 [小程序端内容核心试验](2026-09-23-local-backend-trial.md) 为准，不再把自建域名或开通微信云开发当成业务核心运行的前提。
