# 经文字词接续与字体分工

按本轮确认实施：经轮正文和原文中出现的有意义字词都可以成为入口，使用一次普通点击。保留全屏无限经轮、邻行交错慢转与停驻阅读。经文使用康熙体，解释和操作使用系统正文体。

## 词与原文的关系

构建时为 11,722 条经文生成中文词边界，随原文一起打包。手机不依赖自身的 `Intl.Segmenter` 支持。每个位置只有一组不重叠范围，例如 `物｜有｜本末，事｜有｜终始`；单字、虚词同样可进入。标点与空白不设链接。分词是可继续校订的语言边界，不代表模型已经核实每个词的关联。

`FlowFrame.lexicalBreaks` 保存完整原文中的 UTF-16 边界。`branch.selection` 携带 `start / end / textHash / corpusVersion`，由内容核心对照可信原文验证。相同的字在不同位置有不同身份；视觉换行不会改变身份，跨行词仍对应同一个入口。模型解读更新也不能移动链接。

`open / branch / next` 保持。已核对的词可复用预备关系；其他词先根据字词及前后文确定古义和检索方向，再从真实语料中挑选、核验新经句。不存在相应联系时保留原句并明确提示。原句换出处、截短或扩长，均不能当作新的分支。离线精选仅使用已有人工关系。

## 命中与连续性

- 经轮从与 shader 相同的投影计算逐字范围，再合并为词。只有清晰、正面的原字承担点击；模糊远景和折射副本不参与精确命中。
- `touchstart` 锁定字词并停止当下推进，给出轻微范围反馈。移动超过原有拖动阈值则取消词选择、继续拨动经轮。一次 `touchend` 只接续一次，屏蔽随后重复的 `tap`。
- 等待期间保留原画面。新经句及字体准备完成后沿用既有空间承接；返回恢复父链的位置、流动状态、原文展开和滚动位置。
- 开场解读未完成时也能点词离开。返回这样的父链时，按原链 ID 补完解读，不重新生成一条开场链。
- 原文组件按同一范围触发同一分叉路径。普通字符不添加连续下划线，按下时高亮；句意与联系仍保留原有少量预备入口。

## 字体

经轮继续从字体文件读取轮廓。原文组件、静读经句和已存注脚中的引文使用独立的 `classic-text` 字体栈；句意、联系、个人文字、输入、按钮与状态使用系统无衬线字体。

动态字体分片同时安装到轮廓渲染器和原生文字层，覆盖待读原文。分片随小程序包按需加载，无需 CDN。字体样式直接导入文字组件，避免依赖跨组件的样式继承。

## 验证范围

自动测试覆盖完整原文覆盖率、标点保留、重复字、跨行词、宽窄画布投影、拖动取消、重复点击、过期文本、未完成父链恢复、跨出处重复引文过滤、字体职责与分包大小。

微信开发工具联调调用真实 DS，经轮使用原生 Canvas 触摸事件。开发工具的页面选择器不能直接访问独立文字组件内的文本；原文部分通过真实组件的 `choose → branch` 事件链验证，并检查原生渲染截图及字体样式。此项不能声称等同于手机上手指点选原文。

新字词未预取时需要语境解析、选文与关系核验，不承诺即时返回。真机点击精度、等待体感和古文分词边界仍需持续校订；本轮不扩展所有解释文字的分词入口，不发布正式版。

## 本轮验证结果

104 项小程序测试、16 项内容核心与关系测试通过，应用及脚本类型检查、语法与结构检查通过。真实 DS 模拟器联调通过 10 项检查：开场、追加内容、已有入口、父链恢复、字体与无限流动、精确字词命中、流动 Canvas 触摸分叉、原文组件事件分叉，以及两层返回。

实际点「知止而后有定」中的「止」，接至「大学之道，在明明德，在亲民，在止于至善。」；再从原文中的「大学」接续并两次返回。经文层计算字体为康熙／补字字体栈，解释为系统无衬线体，GL 错误为 0。

开发工具普通整页截图未合成实时 WebGL 层。对此另从真实 Canvas 导出按住字词时的画面，确认原经轮仍完整、选中「止」、时间轴锁定、GL 错误为 0；没有将黑色自动截图当作渲染成功的证据。原文层的字体与排版已查看原生截图。

模型输出不合规范或找不到合适联系时仍可能需要原位重试；本轮曾发现过长的接续方向及重复引文，已加入简短方向约束、用户可读的失败提示和重复引文校验。通过一次真实联调不代表所有字词都已完成语义质量验收。

`auto_preview` 成功推送到当前开发者微信：入口 `pages/connect/index`，主包 938,686 字节，总包 13,341,022 字节，10 个资源分包均小于 2 MiB。临时凭证已移除，URL 校验与热更新恢复原配置。没有提交或推送 Git。

## 真机点击与简体界面修复

用户反馈「有反馈但不接续」后，按手机事件格式复现：旧处理器接收 `{x, y}` 时没有做字词命中，分叉次数为 0，却触发了空白停驻。微信 [官方事件类型](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.event.d.ts) 区分 Canvas 的局部 `x/y` 与普通触摸的页面 `clientX/clientY`。新增 `touch-point.js` 将两者统一到页面坐标，保留按下锁定、拖动取消与一次点击只分叉一次。

此前模拟器验证使用的是浏览器触摸格式，未覆盖这一分支。进一步抓取开发工具触摸助手的实际入参，发现只传 `x/y` 会被该工具转换为 `clientX=0, clientY=0`。现在联调脚本将手机事件直接交给实际页面处理器，不能将其描述为物理真机点击。另通过开发工具窗口实际点击「原文 → 止」，确认进入「物有本末，事有终始」；这是实际原生文字组件点选，而非直接调用 `choose`。

流动中的接续失败原先只在 `paused` 时显示，现已移除该限制。没有离线关系时明确提供「连接 DS」；其他失败可重试或收起。失效的字词位置也清除高亮并说明原因，不再静默返回。

连接页标题、说明、按钮、占位文字及加载状态全部改为简体。页面与解释组件显式选择系统正文字体，经文独立使用康熙体；模型提示要求解释使用简体，引用原字不转换。

联调还捕获到模型返回超长引文：校验返回 `quote: too_big`。内容核心对格式、长度不合格的输出最多纠正一次，仍需通过完整的原文与关系核验；不截断引文、不放宽限制、不重试语义拒绝。自动测试覆盖纠正成功、仍不合格及取消请求，共 109 项小程序测试、18 项内容核心测试通过，类型和结构检查通过。

最终打包代码的真实 DS 联调 10 项全部通过：使用手机坐标格式点「止」接至「大学之道，在明明德，在亲民，在止于至善」，再从原文中的「而后」接续，并两次返回恢复原位置。原文及系统字体现已在原生截图中核对。开发工具实际点选及手机事件格式联调不等同于 iPhone 手指验收，新预览仍需在用户手机复测。
