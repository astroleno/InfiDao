# 六经注我 · 原生小程序

## 已确认目标

用户于本次任务明确授权：结合所提供 React/Three 参考的黑底、玻璃透射与色散，以及 Simon Rogers 的持续上升运动，原生实现微信小程序。后续视觉反馈将形体明确为**竖直转经筒**：五层水平经文环绕同一根竖轴，中间清晰，上下逐层渐弱、渐隐、渐模糊。初始一念之后持续流动，不逐轮要求输入。本轮使用 mock 内容，DeepSeek V4.1 Flash 留待后续接入。

## 设计与模块

- `pages/flow`：单场景中的流动、停驻解读与原文展开；一次输入、拖动回看；原生 WXML/WXSS，没有网页嵌套。
- `flow/scene`：竖直封闭圆柱、水平环绕文字、五层空间焦点；每段经文拆为短句，每圈只呈现一句。
- `flow/renderer`：原生 Canvas WebGL 1；白色字形图集、两个带深度缓冲的离屏场景，分别计算背面和正面的体积折射；不同波长使用不同折射率。前景文字保持白色，色散由玻璃产生。固定竖轴、整体同向旋转并上升；中段减弱折射叠影，保留文字可读性。绘制频率上限约 30 fps，DPR 上限 2。v5：行改为屏幕空间 ribbon 排布——正弦剖面让中段行距均匀、向上下边缘压缩并铺满全屏，行绕自身切线倾倒（中心直立、边缘近平躺且始终朝向读者），离焦行按真实焦距差产生景深模糊与色差；边缘淡出在片元级计算（顶点级插值会把只有两个纵向顶点的玻璃幕墙整体清零）。
- `flow/timeline`：独立时钟；按时间推进，触摸暂停推进、隐藏停止、恢复不快进。
- `flow/provider`：mock provider；`open(seed)` 返回 `{kind, seed, journey, frames, cursor}`，展示层不依赖模型、凭证或网络协议。
- `content/passages`：从项目本地语料选取并保留 sourceId/fullText；三个主题各八段，解读为明确的人工示例。mock 按整组自然回环，不声称无限生成。

视觉：纯黑空间、白色宋体经文、玻璃折射中的青/蓝/暖红色散。流动时不显示标题、品牌副标题、念头摘要、桥接语或解读。首次提示「轻点停驻，读懂这一句」自动消失。轻点后当前短句用 420 ms 归中，其他经句退暗，下方展示完整经句、句意和此刻解读，底部出现「一念 / 原文 / 继续」。

## 连续阅读迭代 · 2026-09-22

用户批准在现有视觉基础上迭代连续性、补充解释，并在迭代前后推送版本。页面状态为 flow → settling → reading → resuming；原文是 reading 的展开层，不再切到另一套静读布局。

- 当前短句是共同的视觉锚点。归中后通过原生 `wx.canvasToTempFilePath` 保存同一帧，等原生 image 解码后才隐藏 WebGL；由此避开原生画布覆盖 WXML 的层级限制。解读淡入时，锚点的像素位置、尺寸和玻璃效果保留。阅读时停止 GPU 绘制。
- 原文展开：同一帧与下方阅读区一起上移最多 160 px，340 ms 完成；下方露出出处、原文及所选经句的高亮。收起反向执行，不更换经句。正常阅读与图形故障静读均按完整段落导航。
- 返回流动：解读 220 ms 退场，原文如已展开先回位；恢复同一画布，再用 240 ms 恢复周围经句，自动流速从零渐增。暂停和拖动在状态切换时重置速度，不依赖已经停止的绘制循环。
- 一念抽屉先挂载再进入，320 ms 后聚焦；关闭有 240 ms 退出期。新主题的旧画面保留到新画面准备完成，以两张原生画面淡接后恢复实时流动。
- `meaning` 与 `reflection` 由 mock provider 按完整段落返回，原文独立；流动短句带有 `passageId / passageQuote / passageLines / lineIndex`，避免停在后半句时丢失语境。
- 所有异步截图、图片解码、动画完成及键盘延迟受动作编号约束；新操作、后台、resize、卸载取消旧回调。迟到的内容请求仍按请求编号校验，并能在回前台后完成。截图承接失败进入可阅读的原生降级状态。
- WXSS 尊重 `prefers-reduced-motion`；停驻是手动静读入口。WebGL 自动流动尚未读取系统的减少动态效果偏好，不声称已验证该平台能力。

实际参考来源：用户提供的 `src/ring.tsx`（圆柱、白字、MeshTransmissionMaterial，thickness=2/backsideThickness=5），[Simon Rogers 原站](https://www.simonrogers.info/) 的逐行 rotateY + translateY 动画，以及用户新指定的转经筒结构；结构核对参考 [Met 藏品](https://www.metmuseum.org/art/collection/search/32640)。最终按用户要求取消斜向/螺旋升角，采用水平文字带和固定竖轴。

本轮在当前仓库增加独立 `miniprogram/`，不需要分支或工作树。使用微信开发者工具原生模拟器验证。用户已指定测试 AppID `wx5f0a423b84cafbef`；当前阶段不上传、不发布、不请求 LLM。

## 验收

2026-09-22 字体迭代：用户明确选择「中间一行大、上下几行小」。缩放跟随每一行距中心的连续距离，上下对称，不按行索引跳变；中间基准为原字号的 1.12 倍，向远端收至 0.62 倍，保留原有位置、旋转、景深与色散。按实际手机相机距离收紧过长经句的字距，中心字形维持同一字号。

用户随后指定复用相邻 CoScroll 的字体。已核对其 `src/app/page.tsx` 的 `DEFAULT_FONT_FAMILY` 和 `@font-face`，实际使用 `public/fonts/润植家康熙字典美化体.ttf`。页面文字、输入和字形图集统一用该字体的随包子集，原字体缺少的五个古字以单独的 Noto Serif SC 子集补齐，不改写原文。使用独立的 webview/native 作用域注册；绘制前等待注册完成，失败回退系统衬线体，避免未加载字体时先画出黑体。未来动态内容需要更新子集或加载完整/分片字体；不新增网络依赖。

用户随后反馈 iPhone 流动段仍是黑体、其他文字正确。修正画布路径：`build-font.py` 从同一源字体导出当前流动用字的笔画轮廓，`flow/glyph-outline.js` 按字体进宽和基线将闭合曲线绘入现有图集。取消画布的 `fillText` 与 native 字体注册依赖，保持 `paintAtlas(canvas, frames, dpr)` 接口、纹理 UV、字号缩放及色散结构。页面仍用已正常工作的 webview 字体。新增用字在构建时验证，缺失轮廓在运行时显式进入原生阅读降级；不接受静默回退黑体。验收包含禁用 Canvas 字体调用后的图集绘制、全部路径与 DPR 覆盖、原生截图及 iPhone 复验。

1. 原生小程序直接编译运行；无 web-view 和 React 运行时依赖。
2. 冷启动自动进入示例流；可输入一念并切换主题；之后无需反复输入。
3. 画面为同轴的五层经文，只显示经典短句；中间清晰，上下对称衰减；中心短句水平对齐。解读、出处和原文位于按需阅读层。
4. 点击停驻并居中/继续，拖动回看，查看原文并关闭后保持原阅读进度；后台不继续推进；整个 mock 周期首尾连续。
5. mock 跨主题有连续语义，经典出处可追溯；不把示例解读当作原文。
6. WebGL 不可用时保留静读与换段能力；故障可重试；静读可由用户主动选择。
7. 测试覆盖时间步进、拖动/回环、生命周期、内容真实性与 provider 边界；记录模拟器视觉与交互结果。
